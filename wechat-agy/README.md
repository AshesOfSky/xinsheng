# 大肥鱼 · 微信群聊 + Antigravity CLI

**Windows 桌面版已提供：**完整解压后运行 `DaFeiYu.exe`，或用 `Install.cmd` 安装桌面快捷方式。
界面包含启停、账号/群聊设置、运行状态、动画表情字典和人格编辑，详见 [桌面版说明](DESKTOP.md)。

在本机通过微信数据库读取一个已配置的群，使用已登录的 Antigravity CLI 账号调用
Gemini 3.8 Flash：闲聊用 `gemini-3.8-flash-low`，认真问题、归纳和成员侧写用
`gemini-3.8-flash-high`。本地 Python 程序负责归档、成员记忆和发送，运行时无需 Codex
或 Antigravity 桌面窗口接管。微信发送仍通过客户端 UIA/输入操作完成。

## 本机使用

- 双击 `启动大肥鱼.cmd`：后台运行。重复启动由进程锁挡住，避免重复回复。
- 双击 `停止大肥鱼.cmd`：停止监听并取消生成中的回复；已经提交的微信发送不能撤回。
- 双击 `查看状态.cmd`：查看当前状态、模型、最近的回复和错误。
- `data/成员侧写.md`、`data/群聊归纳.md`：查看整理后的留档。
- `data/messages/日期.jsonl` 和 `data/archive.sqlite`：原始归档，保留消息 ID 和成员 ID。
- 编辑 `PERSONA.md`：每次回复读取，修改后下一轮生效。
- 编辑 `data/config.json`：修改轮询和参与频率后，停止再启动。

`state=running` 表示监听已开始；`prepared` 只完成归档准备，没有自动回复。
发送结果 `submitted` 表示已提交微信，持续监听读到本次自己的消息后改为 `confirmed`；
`unconfirmed` 表示待核，
程序不会因为结果不明再次发送同一条回复。

## 回复与记忆规则

真实 @ 从消息元数据中的 `atuserlist` 检测，被 @ 时不受普通接话冷却限制。
其他新文字由模型按人格和上下文选择接话。普通消息用约 0.55 秒合并连发，最多等
1.2 秒；普通接话间隔至少 4 秒，等待期间保留最新进展。真实 @ 跳过这段等待。
队列按当前一段讨论处理，不逐条补答；新 @ 会抢占正在生成的普通闲聊。
生成完成时如果群里已经出现新文字，旧草稿不发送，携带未回答的 @ 按最新上下文重写。
自己的消息只归档，不触发机器人回复。最后一条外部文字沉默 5 分钟时只尝试续话一次，
最后一条是机器人自己时不会主动连续自言自语。
@ 的正常生成必须有回答；模型服务、额度或微信发送异常时在状态文件报错，
不宣称投递成功，也不循环重试刷屏。

快速模型会识别需要计算、推理、技术解释、方案比较或认真建议的请求，交给 High 生成；
路由时的草稿不发群。High 在独立后台线程处理，查询期间 Low 继续接新话题；Low 的
上下文标记正在处理的问题，避免反复把同一个问题排队。被 @ 只决定优先级和必须回应，
不把每个玩笑都送去慢档。

High 完成后，按原问题的消息 ID 找到提问者，通过微信原生 @ 选择器选中，再追加正文。
发送前按成员 ID 读取 `chat_room.ext_buffer` 中的当前群昵称，避免用通讯录昵称找错人。
这是带 `atuserlist` 的真实提醒；不会把普通 `@昵称` 文本当成成功。发送回读同时核对
正文和实际成员 ID。只在发送的短暂阶段共用微信输入框，High 思考期间不占用 Low。

需要搜索、打开链接或核查当前事实的问题交给 `wechat-researcher`，实际使用 AGY 的
`search_web` / `read_url_content`，把来源附在回答后。需要联网却没有实际工具调用或
来源时不发送猜测结论。普通接梗仍由 Low 直接完成，归纳和成员记忆仍用 High。
本机 `%USERPROFILE%\.gemini\antigravity-cli\settings.json` 已允许 `read_url(*)`，
使后台 CLI 能读取网页；未启用跳过全部权限检查的参数。

第一次准备时导入这个群在本机可读的历史；运行中持续增量归档。重启时补齐归档，
不会批量补答旧记录；重启时接住尚未归档且不超过 45 秒的普通文字，真实 @ 保留 10 分钟，
用于接回更新间隙的提问。已归档并正在处理的任务目前不在重启后恢复。
收到的原生表情由后台线程自动保存，按微信已有的表情 ID 去重，保留原文件及动图帧。
每张图分配稳定代码 `S001`、`S002` 等；`data/stickers/catalog.json` 对应代码、微信 ID、
原文件、可见文字、画面说明、常见含义、适用/避免场景和识图来源。
`data/stickers/index.html` 是可直接打开的图文表情字典。

AGY High 先实际调用 `view_file` 看图；动图提供按时间顺序抽取的多帧预览。
识别不确定、识图失败或未实际调用看图工具时，自动调用本机已登录的 Codex CLI，
通过 `--image` 识图并返回结构化结果。日常聊天仍由 AGY 托管；指定好友的材料撰写、修改等工作可调用 Codex Astra Ultra。
两边仍看不清的图保留原件和疑点，不进入自动选图候选。后台新图优先，不阻塞 Low 接话。

即时上下文和归纳使用已识别表情的画面与含义，其余媒体保留类型占位，卡片只保留标题；
不把媒体下载凭据发给模型。Low 根据当前语境从候选表情选择代码，程序映射到原文件发送；
代码不写到群里。允许单图或短话配图，不每句硬塞；30 秒内不连发表情，避免重复最近两张。
GIF 作为原生动画表情回读时核对实际表情 ID，静态 JPEG/PNG 由微信作为图片发送。

空闲时尝试将最新的原生表情加入微信“添加的表情”，从本机表情库回读确认；
话题已经推进则跳过历史翻找，优先正常聊天。这个收藏动作与本地可调用表情库分开计数，
不能把下载成功当作微信收藏成功。静态图片消息没有“添加到表情”菜单，仍可从原文件复用。

每积累 50 条待整理消息或经过 10 分钟，调用同一 AGY 模型归纳一批资料。
每批最多 80 条，保存群聊总结以及有新证据的成员观察。用稳定成员 ID 区分同名成员，
每条观察引用原消息编号；没有发言材料的成员标为材料不足。程序拒绝把其他人的消息
或机器人发言作为该成员侧写的证据。观察和总结是模型产物，可以直接查原文核对。

即时回复使用固定人格、最近 18 条精简消息、近期 3 位参与成员及被 @ 对应成员的
最近 3 条观察；完整归纳和来源证据继续留档，不在每轮闲聊里反复塞入全部档案。
模型在云端处理这些上下文；原始数据库、导出的群聊资料和密钥缓存均保存在本机，
这些数据目录已被 Git 忽略。

## 运行条件

Windows、微信保持登录，发送时桌面应处于可操作状态。电脑关机或休眠时不工作。
没有自动配置开机启动。CLI 的账号登录需要有效，实际可用额度以 Antigravity 账号为准。
普通读取不操作微信窗口；发送可能切换焦点/使用剪贴板，不能称为完全无界面协议。

## 开发

Python 3.12，依赖锁定 `wechatauto-replica==1.2.8.1`。

```powershell
uv venv .venv --python 3.12
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
.venv\Scripts\python.exe -m unittest -v test_storage.py test_bridge.py test_context_text.py test_conversation.py test_reply_router.py test_stickers.py
.venv\Scripts\python.exe agy_client.py
.venv\Scripts\python.exe check_database.py
.venv\Scripts\python.exe bot.py --prepare
```

`agy_client.py` 使用合成消息实测模型，不发送微信。`check_database.py` 只读取指定群，
首次会在本机提取读取数据库所需的密钥；输出只含验证统计，原资料留在被忽略的数据目录。
`--prepare` 归档、总结和更新人物资料，不发送消息。普通启动 `bot.py` 会实际自动回复。
桌面模式通过同一个后台进程锁启停，不会与已有源码版重复回复。
`check_network.py` 使用合成问题验证 AGY 原生联网和来源，不发送微信。

CLI 1.4.7 实测：常驻 NDJSON 进程可以连续请求；把 `--json-schema` 与当前自定义 agent
组合使用时会出现重复内部轮次及多段 JSON 拼接，因此这里使用提示中的 schema 和本地
JSON 解析，直接读取每轮 `result`。不通过截取最后一段 JSON 掩盖异常结果。

## 回复速度与发送方式

闲聊与认真回复各用常驻 AGY NDJSON 会话连续处理请求，启动时预热；归纳使用独立的
High 会话。High 在后台预热，不阻塞 Low 接话；无须 Codex 或 AGY IDE 接管。
High 查证同样在独立后台执行，结果通过原问题对应的真实 @ 返回。
读取每 0.35 秒检查数据库，发送使用微信原生 UIA 控件。优先绑定已经打开的目标群独立窗，
否则使用主窗口；发送前要求当前会话就是目标群。文字通过 ValuePattern 定向写入，校验内容
后点击微信发送按钮，不使用全局粘贴或回车。表情和原生 @ 的按键操作核对前台窗口及输入框
焦点，失焦即中止。仍可能激活微信和使用剪贴板，不能称为无界面协议发送。
发送库使用其内置 `fast` 节奏（20 次/120 秒的突发上限），替代默认 6 次/120 秒后额外
等待 30–75 秒的 `natural` 节奏。后台读取自己的新消息确认发送，不再为每次发送另开查询链。

2026-10-26 实测：精简提示的 High 常驻三轮生成约 6.8–8.9 秒；一次真实群回复生成
10.55 秒、UI 提交 1.45 秒、从群友发言到机器人发出共 14 秒。Low 离线比较三轮生成
约 1.8–3.0 秒。随后用户选择闲聊 Low、认真问题和记忆 High，已按此部署。
这些是小样本测量，不是延迟承诺；最终真实调用模型与耗时见状态文件。
